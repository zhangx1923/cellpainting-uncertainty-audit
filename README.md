# Auditing the uncertainty of Cell Painting compound classifiers under laboratory shift

Code for the paper *"Does the Assay Know What the Model Doesn't? Auditing the Uncertainty of Cell Painting Compound
Classifiers Under Laboratory Shift"* (ACM TRUST 2027 submission).

The code trains compound classifiers on JUMP-CP Cell Painting profiles from some laboratories, deploys them on a
laboratory they have never seen (leave-one-laboratory-out), and audits whether their uncertainty survives the move:
calibration, conformal coverage and selective-prediction risk. It then measures how much of the failure the plate's
own control wells can detect and repair:

* **Audit** - accuracy, ECE, AURC, conformal coverage and selective risk on in-distribution plates vs. the unseen lab,
  on all treatment wells and on wells of *active* compounds (defined on training plates).
* **Canary gate** - positive-control accuracy on each deployed plate as a warning signal; plates out of the
  in-distribution range are flagged.
* **Control-anchored conformal recalibration** - rules that use only the deployed plate's control wells (DMSO and
  positive controls, whose identities the plate map records) and no treatment-well label: V1 positive-control Mondrian,
  V2 coverage matching, V3 DMSO-weighted CP, V4 gated matching, V5 activity-split Mondrian, and **V6 plate-standardised
  CP**, plus two labelled oracles for reference.
* **Repair strategies on the model side** - deep ensembles, plate-level augmentation, per-lab DMSO whitening and
  control-anchored feature alignment (`--ens`, `--aug`, `--sphere`, `--align`).

All numbers in the paper are generated by scripts in this repository from the public data.

## Installation

```bash
git clone https://github.com/YOUR-USERNAME/cellpainting-uncertainty-audit.git
cd cellpainting-uncertainty-audit
python3 -m venv .venv && source .venv/bin/activate      # or a conda environment with Python >= 3.10
pip install -r requirements.txt                         # install the torch build that matches your CUDA version
```

Tested with Python 3.12, PyTorch 2.4 and one NVIDIA RTX 4090 (24 GB). A leave-one-laboratory-out fold takes about
40 s on an idle machine; the CPU-only path works but is slower.

## Data (public, about 6 GB)

```bash
bash scripts/download_data.sh             # JUMP metadata + 141 TARGET2 plate profiles -> data/, then builds data/target2_wells.parquet
bash scripts/download_data.sh --harmony   # optional: consortium Harmony profiles for the transductive baseline
```

Sources: JUMP-CP `cpg0016-jump` well-level CellProfiler profiles from the Cell Painting Gallery
(`s3://cellpainting-gallery`, no credentials needed), metadata from
[jump-cellpainting/datasets](https://github.com/jump-cellpainting/datasets) and
[jump-cellpainting/JUMP-Target](https://github.com/jump-cellpainting/JUMP-Target), and MoA annotations from the
Drug Repurposing Hub via [broadinstitute/lincs-cell-painting](https://github.com/broadinstitute/lincs-cell-painting).
Please cite the original data papers when you use the data.

## Reproducing the paper

```bash
bash scripts/reproduce_all.sh
```

runs every experiment and regenerates `paper/figures/`, `paper/tables/` and `paper/numbers.tex`. The individual steps:

| step | command |
|---|---|
| main sweep (11 labs x 3 seeds) | `python3 experiments/loso.py --seeds 0 1 2 --outdir experiments/results/loso_v5 --save-wells` |
| 64-component classifier | `python3 experiments/loso.py --pcs 64 --seeds 0 1 2 --outdir experiments/results/loso_pcs64 --tag _pcs64 --save-wells` |
| model-side repairs | `python3 experiments/loso.py --seeds 0 1 2 --outdir experiments/results/strat --tag _aug3ens5 --aug 0.3 --ens 5` (screen: `--ens 5`, `--aug 0.3`, `--aug 0.5`, `--sphere lab`, `--align lab`) |
| aggregation | `python3 experiments/aggregate.py --dir <results dir> [--tag <tag>] --out experiments/results/summary/<name>` |
| oracles, V6, laboratory-level statistics, canary | `python3 experiments/analysis_revision.py` |
| anchor-distance analysis | `python3 experiments/analysis_anchor_gap.py` |
| repair comparison | `python3 experiments/screen_compare.py --dir experiments/results/strat --seeds 0 --out experiments/results/summary/repair` |
| figures / tables / numbers | `python3 experiments/figures.py; python3 experiments/make_tables.py; python3 experiments/make_numbers.py` |

`experiments/results/summary/` contains the aggregated CSV/JSON summaries used for the paper, so figures, tables and
numbers can be regenerated without re-running the GPU sweep.

## Repository layout

```
experiments/
  common.py               data loading, per-plate DMSO normalisation, feature selection, metrics
  prepare_data.py         assemble the TARGET2 well table from the downloaded plates and metadata
  loso.py                 leave-one-laboratory-out audit: classifier, conformal rules V1-V6, canary gate, selective prediction
  aggregate.py            per-fold JSON -> CSV summaries
  analysis_revision.py    oracles, V6, laboratory-clustered statistics (bootstrap over labs, Wilcoxon), canary correlations
  analysis_anchor_gap.py  control/treatment score distances and activity-split robustness
  screen_compare.py       comparison of model-side repair strategies
  figures.py, make_tables.py, make_numbers.py   paper figures, LaTeX tables and number macros
paper/figures/specs/fig_pipeline.json          FigureSpec source of the pipeline figure
scripts/download_data.sh, scripts/reproduce_all.sh
```

Paths are resolved relative to the repository root; set `TRUST_ROOT=/path/to/repo` to override.
